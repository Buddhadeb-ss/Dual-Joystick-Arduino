# Code Analysis and Working

The program transforms the Arduino Uno and two analog joystick modules into a virtual game controller for a computer. The joystick positions are continuously read, converted into IBUS-compatible channel values, packed into a valid IBUS data frame, and transmitted through the USB serial connection. The vJoySerialFeeder software running on the computer receives this data and creates a virtual joystick that can be used by games and simulators.

## Serial Communication Initialization

The setup function initializes serial communication at a baud rate of 115200 bps.

```cpp
void setup() {
    Serial.begin(115200);
}
```

This communication channel serves as the link between the Arduino and the computer. All controller data is transmitted through this serial connection.

## Reading Joystick Inputs

Inside the main loop, the Arduino continuously reads the analog voltages generated by the joystick modules.

```cpp
channels[0] = map(analogRead(A5), 0, 1023, 1000, 2000);
channels[1] = map(analogRead(A4), 0, 1023, 1000, 2000);
channels[2] = map(analogRead(A2), 0, 1023, 1000, 2000);
channels[3] = map(analogRead(A3), 0, 1023, 1000, 2000);
```

The analog-to-digital converter (ADC) of the Arduino produces values between 0 and 1023. These values are mapped to a range of 1000–2000, which is the standard range used by RC transmitters and the IBUS protocol.

### Channel Assignment

| Channel | Function | Pin |
| ------- | -------- | --- |
| CH1     | Roll     | A5  |
| CH2     | Pitch    | A4  |
| CH3     | Throttle | A2  |
| CH4     | Yaw      | A3  |

The center position of a joystick corresponds approximately to a value of 1500.

## Auxiliary Channels

Two additional channels are included for future expansion.

```cpp
channels[4] = 1500;
channels[5] = 1500;
```

These channels remain fixed at the neutral position and can later be assigned to switches, buttons, or additional controls.

## IBUS Packet Construction

An IBUS packet consists of 32 bytes.

```cpp
buffer[0] = 0x20;
buffer[1] = 0x40;
```

The first byte indicates the packet length (32 bytes), while the second byte specifies that the packet contains channel data.

The joystick values are then inserted into the packet.

```cpp
for (int i = 0; i < 6; i++) {
    buffer[2 + 2 * i] = channels[i] & 0xFF;
    buffer[2 + 2 * i + 1] = (channels[i] >> 8) & 0xFF;
}
```

Each channel value is stored as a 16-bit number and therefore occupies two bytes inside the packet.

For example:

```text
1500 = 0x05DC
Low Byte  = 0xDC
High Byte = 0x05
```

This allows the receiver to reconstruct the original channel value accurately.

## Filling Unused Channels

The IBUS protocol supports up to fourteen channels. Since only six channels are actively used, the remaining channels are assigned a neutral value.

```cpp
for (int i = 6; i < 14; i++) {
    buffer[2 + 2 * i] = 0xDC;
    buffer[2 + 2 * i + 1] = 0x05;
}
```

The hexadecimal value 0x05DC corresponds to 1500, ensuring all unused channels remain centered and stable.

## Checksum Generation

To ensure reliable communication, a checksum is calculated.

```cpp
uint16_t checksum = 0xFFFF;

for (int i = 0; i < 30; i++) {
    checksum -= buffer[i];
}
```

The checksum is generated by subtracting all packet bytes from 0xFFFF. This value is then stored in the final two bytes of the packet.

```cpp
buffer[30] = checksum & 0xFF;
buffer[31] = (checksum >> 8) & 0xFF;
```

The receiver performs the same calculation and compares the result with the transmitted checksum. If the values do not match, the packet is considered corrupted and is discarded.

## Data Transmission

After packet construction is complete, the packet is transmitted through the USB serial interface.

```cpp
Serial.write(buffer, 32);
```

The complete 32-byte IBUS frame is sent to the computer where vJoySerialFeeder interprets the channel data.

## Refresh Rate

```cpp
delay(4);
```

A delay of 4 milliseconds results in an update frequency of approximately 250 Hz.

```text
1000 ms / 4 ms ≈ 250 updates per second
```

This high refresh rate provides smooth and responsive control for gaming and simulation applications.
